# Project evidence

This index distinguishes executed model experiments, correctness checks and evaluation paths that still need data or provider access. Results below were recorded on 7 November 2026. Hardware-dependent timings apply only to the environment saved in each report.

## Executed experiments

| Project | Result and scope | Raw report | Executed run |
|---|---|---|---|
| MNIST CNN | 98.50% on the full 10,000-example test set; one seed | [Metrics, confusion matrix, training history](https://github.com/Almizan-khan/CNN-with-PyTorch/blob/main/reports/mnist-test.json) | [Training](https://github.com/Almizan-khan/CNN-with-PyTorch/actions/runs/42401091003) |
| Transformer | 87.95% token accuracy / 68.75% exact match on 256 synthetic copy sequences; 2,000 steps | [Autoregressive evaluation](https://github.com/Almizan-khan/transformers-from-scratch/blob/main/reports/copy-2000.json) | [Tests and experiment](https://github.com/Almizan-khan/transformers-from-scratch/actions/runs/42401095749) |
| DNA Transformer | Test masked-token loss 4.8491 vs frequency baseline 4.9527; E. coli, small budget | [Data hash, configuration and metrics](https://github.com/Almizan-khan/-DNABERT-Style-Transformer-From-Scratch/blob/main/reports/ecoli-small.json) | [Genome experiment](https://github.com/Almizan-khan/-DNABERT-Style-Transformer-From-Scratch/actions/runs/42401778845) |
| Tabular regression | Five-fold OOF RMSE across three seeds; fixed parameters and no evaluation-fold early stopping | [Mean, Ridge and CatBoost](https://github.com/Almizan-khan/Gradient-Boosting-pipeline/blob/main/reports/diabetes-fixed-budget.json) | [Tests and comparison](https://github.com/Almizan-khan/Gradient-Boosting-pipeline/actions/runs/42401858794) |

MNIST is an introductory dataset. Copying random tokens is a controlled algorithm task. Single-genome MLM loss is not a biological-function benchmark. The diabetes dataset is a small public regression reference and these models are not medical tools. Cross-project metrics are not interchangeable.

## Correctness and operational checks

| Project | Tests | What the checks establish |
|---|---:|---|
| CNN | 4 | Finite gradients, normalized predictions, checkpoint round trip and evaluation bookkeeping |
| CatBoost | 4 | Feature schema, categorical handling, OOF/model reload behavior |
| Transformer | 5 | Attention reference agreement, causal/padding masks, embeddings and serialization |
| DNA Transformer | 6 | Disjoint coordinates, reproducible masking, token mapping, gradients and padding |
| InsightWeaver | 6 | Five stages execute once, fan-in is complete, invalid/provider-failure paths are surfaced |
| Rule classifier | 6 | Cross-entropy semantics, stable probabilities, group isolation and metric validity |
| Wellness demo | 9 | Persistent sessions, conflict handling, input validation, deletion and safe rendering |
| DreamBooth workflow | 5 | Image validation, duplicate detection, manifests, CLI arguments and prompt validation |

**45 tests in total** across eight independent Python 3.11 CI suites. These checks do not establish deployment readiness or the quality of unexecuted model experiments.

[InsightWeaver offline report](https://github.com/Almizan-khan/insightweaver-agent/blob/main/reports/offline-workflow.json) measures graph overhead with fixed responses. [Wellness offline report](https://github.com/Almizan-khan/-Mental-Health-Assistant/blob/main/reports/offline-api.json) measures in-process API/storage work. [Classifier architecture report](https://github.com/Almizan-khan/Rule-Violation-Classifier/blob/main/reports/architecture-latency.json) measures a tiny random test model. None is represented as live-model quality or production latency.

## Experiments requiring additional inputs

- Rule classification: the actual competition training/test data, accepted dataset terms, and a full pretrained-model training run. Historical leaderboard claims are preserved but not presented as reproduced.
- InsightWeaver: provider access and a fixed, human-reviewed case set for quality/cost comparisons against a single-call baseline.
- DreamBooth: permissioned training images, held-out references, GPU training and the paired image set.
- Wellness provider: optional provider access for integration testing; no clinical-effectiveness claim is made.

Raw reports are committed with source commit IDs and run URLs. Checkpoints are generated by reproducible commands and stored as workflow artifacts when configured; GitHub's retention policy can expire those binary artifacts. Original experiments and descriptions remain available in project history and provenance files.
